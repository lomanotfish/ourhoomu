## Findings

### 1. Stale mutations can override the current identity's UI

SEVERITY: HIGH

FILE: `ourhoomu-front/app/api.tsx`

LOCATION: `signOut` lines 191–215; `createHouse` lines 218–247; `acceptInvite` lines 250–265; `revokeInvitation`, `leaveHouse`, `renameHouse` lines 300–370.

ISSUE: These handlers still settle without a live identity/generation guard. `createHouse` line 222 compares against captured `authGeneration`; `revokeInvitation` line 309 compares against captured `activeHouse`. Other listed handlers have no settlement guard.

IMPACT: Start rename/leave/accept as identity A, change identity, and resolve A's request. Its continuation can call captured `load()`, increment shared `loadGeneration`, supersede B's load, then discard its own result because its auth generation is obsolete. Late errors can clear the current UI; a pending old logout can force signed-out state/navigation after a newer identity has been accepted. This sequence follows the actual handler code; no mounted-device/browser reproduction was run in this review.

RECOMMENDED_FIX: Pi frontend owner must apply one consistent live operation guard to every asynchronous handler. Check before all post-await state writes, stale `load()`/detail calls, catch processing and finally cleanup. Include current auth/runtime identity and operation generation; house-scoped settlements also require the live active house. Preserve immediate local sign-out while guarding its delayed remote completion.

### 2. Invalidating an operation can permanently retain busy state

SEVERITY: MEDIUM

FILE: `ourhoomu-front/app/api.tsx`

LOCATION: generation reset lines 41–51; `clearAuthenticatedData` lines 53–68; guarded mutation/error/finally paths; retry controls lines 486 and 493.

ISSUE: Invalidation increments `dataGeneration` without clearing `busy`. A terminal 401 from `loadAccounts`, `createInvitation`, `saveAccount` or `changeAccountActive` calls `clearAuthenticatedData`; their guarded finally then skips `setBusy(false)` because their operation is obsolete.

IMPACT: Retry/actions can remain disabled after terminal authorization failure. The generation-reset effect also retains account-editing/form values across external auth-generation changes.

RECOMMENDED_FIX: Reset busy and authenticated form/error state in the central auth/runtime invalidation path. Obsolete finally blocks must remain unable to overwrite a newer operation's busy state.
