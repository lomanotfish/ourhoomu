SW-0010 owns bill/payment adapters and bill routes; SW-0011 owns chores/activity/dashboard adapters and routes. Lead assigns one owner for shared contracts/layout/lockfile. Do not import `demo/types.ts` as wire DTOs: map server membership IDs, versions, status and permissions into view models; keep `DemoProvider` separate for previews. API operations return `Promise<Result<T, ApiError>>` or throw a typed `ApiError`, never pretend mutation success from local state. Display server supplied balances and share allocations, with local `parseSatang`/`parseBps` only as input and preview helpers; send safe integer satang/bps and revalidate 10,000 bps on server. Do not derive paid from HTTP success or pending attempts.

Suggested client contract: `SessionRepository` (`bootstrap`, `exchange`, `refresh`, `logout`, `me`); `HouseRepository` (`list`, `create`, `acceptInvite`, `detail`, `members`, `rename`, `recipientAccounts`, `selectableRecipientAccounts`); `BillRepository` (`list`, `detail`, `createDraft`, `patchDraft`, `publish`, `payments`, `requestPayment`, `cancelPayment`, `confirmCash`, `rejectCash`, `uploadSlip`, `verify`, `reconcile`, `fetchSlip`); `ChoreRepository` (`list`, `previewSchedule`, `createSchedule`, `createManual`, `complete`, `reopen`); `ActivityRepository` (`dashboard`, `list`, `markRead`). All house reads take an explicit house ID and cursor/filter; no silent fallback to first house after a revoked membership. Mutation DTOs carry `expectedVersion` where specified and a stable idempotency key for each user intent, reused on network retry, regenerated for a new intent.

## Network, cache and state policy

Use a discriminated `LoadState<T>` with `idle | loading | ready | refreshing | stale_offline | empty | error`, plus mutation `idle | submitting | pending_server | succeeded | failed`. Render independent skeleton/loading, true empty, retryable error and stale cached state in each screen. Preserve cached read-only house data only while session and membership remain valid and item expiry has not passed; cache key includes user, house, resource and filters/cursor. Do not cache slip bytes or full account numbers on disk. On logout, token revocation, account switch, 401 after one serialized refresh, 403 membership loss, or 410 expiry, clear affected memory/disk cache, slip image memory, pending navigation and active house; invalidate all house queries after house switch or membership refresh. Never show another house's stale data while next house loads. A 404 out of scope should look unavailable, not imply existence. A 409 displays current authorized version and prompts reload/reapply; 429 respects `Retry-After`; network timeout on payment requests retains idempotency key and checks server attempt before retry. Disable duplicate submit taps. Offline allows marked, nonexpired read cache only; no local money, cash confirmation, schedule completion or other queued mutations. Manual pull refresh and app foreground trigger membership/dashboard/activity/bill/chore revalidation; refresh rotation is single-flight, protected routes wait for bootstrap. `202` or `pending_verification` remains pending until the server reports confirmed. Cash awaits creator confirmation even if payer submitted it. Rejected/needs-attention expose server reason without leaking other users' payment details.

Use UTC ISO timestamps for audit/activity, but send/display chore occurrence and bill due date as validated calendar dates in the house's timezone (proposed D2 still awaits approval). Replace device-dependent `dateOffset` for live filters with a house-timezone calendar service; never parse date-only strings through UTC `Date` for day selection. Keep current `ChoreDatePicker` visual and motion. Local allocation preview can use existing `money.ts`, while published snapshots and remaining balance always come from server. Slip fetch must send bearer token, use no-store/memory-only viewing, and wipe viewer on background/house switch/logout/403/410.
