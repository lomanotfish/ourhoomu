# ตั้งค่า monorepo และ toolchain ที่รันได้

## Ready gate

ยังไม่เริ่มงาน ผู้ใช้อนุมัติเฉพาะเอกสาร ต้องยืนยัน design revision/ขอบเขตนี้ก่อน พร้อม prerequisite tickets ที่ Tech Lead ตรวจรับจริง ไม่ใช่แค่ runtime succeeded

- Owner: platform-engineer; ไม่ใช่ assignment/dispatch ที่เกิดขึ้นแล้ว
- Scope / allowed edits: Root manifests/lockfile/workspace/CI, initial ourhoomu-api/supabase config และ ourhoomu-front scaffold เท่านั้น
- Contracts: [requirements](../requirements.md), [domain](../../project/domain.md), [API v0.1](../../project/api-contract.md)
- Dependencies: design approval
- Worktree/branch/base SHA/target: Tech Lead เติมจาก receipt จริงก่อนเปลี่ยน ready; ใช้ worktree แยกตาม ownership และตรวจ target ณ เวลานั้น ห้ามใช้ SHA ของเอกสารเป็นฐานถาวร
- ทุก worker ไม่ได้ทำงานคนเดียวใน repo รักษางานของผู้อื่นและขอบเขตไฟล์ ไม่ revert ผลของ ticket อื่น
- Shared migrations/lockfile/contract ต้องมี owner เดียว หากต้องเปลี่ยนส่วนของ owner อื่นให้ Tech Lead จัด assignment ก่อน

## Verification / review

install แบบ frozen lockfile, lint/typecheck, local Supabase status และ iOS smoke ตาม scripts ที่สร้าง

Tech Lead ตรวจ diff กับ acceptance ก่อน merge ผู้ตรวจเป็นคนละ owner ตามความเสี่ยง ทดสอบหลังรวมที่ target จริง เก็บ artifacts ถาวรก่อน release/cleanup ใช้ [agent guide](../agent-guide.md)

## Execution และ checkpoint

- Mode / Run / Task / Dispatch: ยังไม่มี ไม่สร้าง IDs จาก template
- Requested/effective model & permissions: pending actual launch receipt
- Graft: pending ใน worktree ของ ticket; preflight แล้วรายงาน command/status/result
- Worker tip / changed files / report: pending
- Required check commands/results: pending
- Ready / review / integration / cleanup evidence: pending
- Retry causes / blocker owner / next action: รอ design approval และ prerequisites ข้างต้น
